# Mentis v0.6.0

Documentation read from links, duplicate uploads refused, a cleaner document page and a more reliable answer check. **Migration 0014.**

## Added

- **Add from link** (Documents): a public https page or file (web page converted to Markdown, Markdown/text, PDF, JSON, YAML, CSV; GitHub file links read from raw). Checked for changes every 6 hours, day (default) or week, or only with **Check now**; a change becomes a new version through the usual approval. A page that cannot be read keeps the version in use and shows *Link not read*. Public addresses only, 20 MB at most.
- **Max check tokens** (customer **LLM** page, answer check section): how long the checker's reply may be, per group of 10 statements. Empty = 2500, or the checker's own limit if higher.
- **Logs that say why** an answer or a check came back empty or cut (stop reason, tokens, limit).

## Changed

- **Duplicate uploads**: a file identical to any document or version of the customer, under any name, is refused with the one it matches.
- **Document page**: one column; header with state and facts, **Upload a new version** in ⋯, the **Read from a link** panel above the tabs.

## Fixed

- **"Check not available" on long answers**: statements are checked in groups, with one retry on an empty reply and a 150 s budget.
- **Answer check**: headings and lead lines are checked against their items' passages; no citations borrowed from another section; code blocks are not statements; values in tables are checked; marks never inside code, links or source numbers.
- **Config import** of an older export keeps the settings it does not contain.

## What changes for you

- Existing documents, chats and settings are unchanged.
- Tenant admins see **Add from link** next to **Upload files**.
- The `worker` and `api` containers need outbound HTTPS to the sites of linked documents.

## Before the upgrade

```bash
cd ~/mentis
git status --short
./backup.sh
```

## Upgrade

```bash
cd ~/mentis
git fetch --tags
git checkout v0.6.0
docker compose up -d --build --remove-orphans
docker compose ps
docker image prune -f && docker builder prune -f
```

## Post-upgrade check

```bash
sudo ./check.sh
docker compose exec api python -c "import app; print(app.__version__)"
docker compose exec postgres psql -U mentis -d mentis -c "select version_num from alembic_version"
docker compose logs api worker | grep -i -E "alembic|error|traceback" | tail -10
```

Expected: `0.6.0`; `0014`; no new errors. In the browser: **Documents → Add from link** with a public page (e.g. a GitHub README) shows the document *from link* with the **Read from a link** panel; uploading the same file twice is refused; a long answer shows the check result instead of *Check not available*.

## Rollback

v0.6.0 adds migration 0014: older images do not start on the upgraded database. Go back with the backup taken before the upgrade:

```bash
cd ~/mentis
git checkout v0.5.2
./restore.sh "$(ls -1dt backups/mentis-* | head -1)"
docker compose up -d --build --remove-orphans
```
