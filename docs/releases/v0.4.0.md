# Mentis v0.4.0

Integrations: in a chat on one customer, `#` reads its ticketing, EDR and identity tools (read only) and the answer links every ticket, host, alert, IP or user it used.

## New

- **`#` in the chat**: choose one or more of the customer's integrations; ask about a ticket (INC0012345, SOC-123), a host, an alert or open alerts. Records are cited like documents, marked *live* in the Sources panel, and checked by the answer check.
- **Links**: the record's id in the answer opens it in the product (ServiceNow, Jira, Falcon console, Defender portal, Vision One Workbench); device and IP pages too where the product has them (Defender). If the answer does not link a record it cites, an **Open:** line under it does. Only links of records actually found are clickable.
- **Six plugins**: ServiceNow, Jira (Cloud and Data Center), CrowdStrike Falcon, Microsoft Defender for Endpoint, Trend Vision One, Microsoft Entra ID (users, MFA, risk, sign-ins).
- **Super-admin → Integrations**: enable the types tenant admins may use (all off after the upgrade).
- **Tenant admin → Integrations**: add, Test, Try a lookup, turn off, delete. Credentials encrypted, never shown again, sent only to the address they were saved for.
- **Documents → download**: each document as Original, Markdown or JSON; **All** downloads every document in use as a ZIP (originals, Markdown or JSON), to reuse the documentation elsewhere.
- Service status: a line per integration. Logs: every lookup (`integration.called`, object ids only).

## Security

- The core lets plugins only read: GET, plus POST only to declared read URLs (sign-in tokens, alert queries); only to the integration's own addresses; no redirects; time, request and size limits.
- Integrations are used only in chats on their own customer, re-checked on every question.
- Ticket and alert text is data, never instructions; links not belonging to the records found are removed from answers.
- Configuration export never contains integration credentials.

## Before the upgrade

```bash
cd ~/mentis
git status --short          # must print nothing
docker compose version      # 2.17 or later (needed to build the api image with the plugins)
docker compose ps
./backup.sh
```

## Upgrade

```bash
cd ~/mentis
git fetch --tags
git checkout v0.4.0
docker compose up -d --build --remove-orphans
docker compose ps
docker image prune -f && docker builder prune -f
```

## Post-upgrade check

```bash
sudo ./check.sh
docker compose exec api python -c "import app; print(app.__version__)"     # 0.4.0
docker compose exec postgres psql -U mentis -d mentis -c "select version_num from alembic_version"     # 0013
docker compose exec api python -c "from app.connectors import registry; print(sorted(registry.connectors()))"
# ['crowdstrike', 'defender', 'entraid', 'jira', 'servicenow', 'trendmicro_visionone']
docker compose logs api | grep -i -E "alembic|error|refusing|plugin" | tail -5
```

In the browser (Ctrl+F5):

1. Super-admin → **Integrations**: enable the types you need.
2. Tenant admin of a customer → **Integrations** → **Add integration**, then **Test** and **Try a lookup** with a real ticket or host.
3. Chat on that customer → `#` → choose it → ask *What is the status of <ticket>?*: the answer cites the ticket and its number opens it in the product.
4. Service status shows the integration; Logs show `integration.called`.
5. Documents → a document → download icon → **Markdown**; then **All** → **JSON**: a ZIP with one file per document in use and `manifest.json`.

The `api` container needs outbound HTTPS to each customer's systems (see INSTALL, *Integrations*).
