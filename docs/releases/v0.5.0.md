# Mentis v0.5.0

New document formats: Markdown, JSON, CSV, TSV, YAML and pictures (PNG, JPEG). No migration.

## Added

- **Markdown** (`.md`, `.markdown`): one section per top-level heading, code blocks kept intact.
- **JSON**: a Mentis JSON export is read back with its pages, OCR scores, tables and flags, so documentation moves between customers or installations without loss. Any other JSON becomes readable text (one section per key or item, lists of records as tables).
- **CSV / TSV**: one table, like an Excel sheet; comma, semicolon, pipe and tab detected; up to 5,000 rows and 500 columns.
- **YAML** (`.yaml`, `.yml`): Sigma rules, SOAR playbooks, configurations. One section per YAML document, named after its `title`, `name` or `id`, text and comments kept as written.
- **Pictures** (PNG, `.jpg`, `.jpeg`): read with OCR and a confidence score, shown in the preview; phone photos turned upright.
- Code blocks are kept whole in the indexed passages (a `#` comment inside YAML or a script is no longer a heading).

## Security

- Every new format is checked at upload: UTF-8 text that must parse, no binary content, empty files refused; pictures checked from the header and refused above 50 million pixels.
- YAML is read as text and never turned into objects: no tags run, anchors are never expanded; at most 200,000 values and 100 nesting levels, counted before anything is built.
- Upload checks no longer run on the API's main loop: a heavy file cannot stall other users.
- The v0.4.1 security fixes are unchanged; text from the new formats goes through the same passage neutralisation in the answer and checker prompts.

## Fixed

- Renaming keeps the type across aliases (`.yml` ↔ `.yaml`, `.jpeg` ↔ `.jpg`, `.markdown` ↔ `.md`).
- Downloads of originals keep non-ASCII file names; the originals ZIP keeps the uploaded extension; customer names with a dot (e.g. "Contoso.Holding") are no longer cut in ZIP names.
- **New version** offers only files of the document's type.

## What changes for you

- Docling (`MENTIS_PARSER=docling`) reads PDF and Office files only; the new formats always use the standard readers.
- A picture with no readable text ends as **Failed**: Mentis answers from text only.
- Documents already uploaded are not read again; their passages change only if you **Retry** or upload a new version.

## Before the upgrade

```bash
cd ~/mentis
git status --short
./backup.sh
```

## Upgrade

```bash
cd ~/mentis
git fetch --tags
git checkout v0.5.0
docker compose up -d --build --remove-orphans
docker compose ps
docker image prune -f && docker builder prune -f
```

## Post-upgrade check

```bash
sudo ./check.sh
docker compose exec api python -c "import app; print(app.__version__)"
docker compose exec api python -c "import yaml; print(yaml.__version__, yaml.__with_libyaml__)"
docker compose exec worker python -c "import yaml, PIL; print(yaml.__with_libyaml__, PIL.__version__)"
docker compose logs api worker | grep -i -E "error|traceback" | tail -10
```

Expected: `0.5.0`; `True` for libyaml in both containers; no new errors. In the browser: Documents → upload a `.csv`, a `.yml` and a screenshot (`.png`): each ends as **Ready**, the CSV as a table, the YAML in a code block, the screenshot with its picture in **Preview** and the text in **Text read**.

## Rollback

v0.5.0 has no migration: going back to v0.4.1 needs no restore.

```bash
cd ~/mentis
git checkout v0.4.1
docker compose up -d --build --remove-orphans
```

Documents uploaded in the new formats stay usable in answers, but v0.4.1 cannot read them again (**Retry** fails) and refuses new versions of them.
