# Mentis v0.3.2 – security release

## What is new

- **Tenant separation verified**: an automated test calls every API route (80) as nine kinds of user, also with ids of other customers' objects (about 2,400 requests per run). No way to read another customer's data was found.
- **Fixed leaks**: answers about a customer removed from a user stayed readable in their old chats (now hidden, also from search and from the LLM history); errors showed internal addresses and provider replies to analysts (now plain messages, details in Logs).
- **Penetration test** (report `docs/security/pentest-v0.3.2.md`): sign-in rate limit per IP (30/min), no account enumeration through "Forgot password", stored API keys never sent to another address, memory cap for huge PDF pages, malformed requests answered 4xx, safer file names and prompt tags.
- **Infrastructure**: databases, Qdrant, MinIO, Redis and embeddings on an internal network (not reachable from the web container nor from Equalizer's network), Mentis refuses to start with default secrets, containers without root privileges, supported nginx, pinned images, updated libraries, owner-only and optionally encrypted backups, new Security section in `check.sh`.
- **Frontend**: API answers never cached by the browser, customer choice not shared between users on the same PC, fixed a freeze with some answers and a chat race.
- Upload notice clears when processing ends; smaller embedding batches (less memory).

## Before the upgrade


```bash
cd ~/mentis
chmod 600 .env
grep -n CHANGE_ME .env || echo "no placeholders"     # must print "no placeholders"
# Qdrant version now running (must be 1.19.x or 1.20.x: Qdrant upgrades one minor version at a time)
docker compose exec -T api python -c "import os,urllib.request as u; print(u.urlopen(u.Request('http://qdrant:6333/', headers={'api-key': os.environ['MENTIS_QDRANT_API_KEY']})).read().decode())"
./backup.sh
```

If Qdrant reports a version older than 1.19, or newer than 1.20, stop and tell the developer before upgrading.

## Upgrade

```bash
cd ~/mentis
git fetch --tags
git checkout v0.3.2
docker compose up -d --build --remove-orphans
docker compose ps
./check.sh
```

`docker-compose.override.yml` (web on `equalizer_edge`) keeps working unchanged; Caddy needs no change.

## Post-upgrade check

```bash
./check.sh        # every line OK, including the new "Security" section
# Data stores are no longer reachable from the web container (must print "isolated"):
docker compose exec -T web sh -c 'wget -q -T 3 -O- http://qdrant:6333/ >/dev/null 2>&1 && echo REACHABLE || echo isolated'
docker compose exec -T web id -u              # 101 (nginx not root)
```

```bash
docker compose logs api | grep -i -E "alembic|error|refusing" | tail -5
docker compose exec api python -c "import app; print(app.__version__)"     # 0.3.2
```

Then sign in, open a chat answer with sources, and upload a small document (worker and `/tmp` in memory).

## Rate limit

Sign-in, 2FA, password reset and invitation requests are limited to 30 per minute per client IP (`MENTIS_AUTH_RATE_PER_MINUTE` in `.env`, `0` = off). Raise it if many users sign in from the same NAT address at the same moment.

## Optional: encrypted backups

```bash
sudo apt install -y gnupg
( umask 077; openssl rand -base64 32 > ~/.mentis-backup-pass )
echo "MENTIS_BACKUP_PASSPHRASE_FILE=$HOME/.mentis-backup-pass" >> .env
./backup.sh        # writes backups/mentis-<date>.tar.gpg
```

Copy the passphrase file somewhere off the server: without it the backups cannot be restored.

## If something fails

- `docker compose logs --tail=50 api`: "Refusing to start with insecure settings" names the secret to set in `.env` (`openssl rand -hex 32`), then `docker compose up -d`.
- Uploads or OCR fail with "No space left on device": raise `MENTIS_API_TMP_SIZE` / `MENTIS_WORKER_TMP_SIZE` in `.env` (defaults 512m / 1g), then `docker compose up -d`.
- Roll back: `git checkout v0.3.1 && docker compose up -d --build --remove-orphans` (volumes are unchanged).
