# Mentis v0.6.2

Security release after a review of 0.6.1 (`docs/security/review-v0.6.1.md`). **Migration 0015.**

## Security

- **Documents are read in a separate process** with memory and CPU limits, and every reader caps what it produces. A crafted Word file or web page (merged cells, deeply nested tables, very wide rows) fails on its own with a clear message instead of stopping the worker shared by every customer.
- **Users and invitations with no customer** are managed only by super-admins and tenant admins of all customers.
- **Deleting a document or a customer** also removes the saved answers that used it; the questions stay.
- **Saved answers** remember every customer they read: they are hidden from anyone who no longer sees one of them, also through a shared link. "All customers" chats are titled with the question. Shared links close on a disabled customer.
- **Tokens** of invitations, password resets and shared links are masked in the logs.
- **Upgrades now pull the current base images**, so their security fixes arrive (see the upgrade block below). HSTS added to the reverse-proxy examples.

## What changes for you

- A tenant admin of the General Knowledge Base alone no longer manages users.
- Answers from deleted documents show "This answer was removed".
- New optional settings in `.env`: `MENTIS_PARSE_MEMORY_MB` (default 2048), `MENTIS_PARSE_CPU_SECONDS` (default 1500).

## Before the upgrade

```bash
cd ~/mentis
git status --short
./backup.sh
```

## Upgrade

```bash
cd ~/mentis
git fetch --tags
git checkout v0.6.2
docker compose build --pull
docker compose pull --ignore-buildable
docker compose up -d --remove-orphans
docker compose ps
docker image prune -f && docker builder prune -f
```

## Post-upgrade check

```bash
sudo ./check.sh
docker compose exec api python -c "import app; print(app.__version__)"
docker compose exec postgres psql -U mentis -d mentis -c "select version_num from alembic_version"
docker compose logs api worker | grep -i -E "alembic|error|traceback" | tail -10
```

Expected: `0.6.2`; `0015`; no new errors. Then upload a document: it must reach *Ready*. If it fails with "needs more memory or time", set `MENTIS_PARSE_MEMORY_MB=3072` in `.env` and run `docker compose up -d worker`.

## Rollback

Migration 0015 is in this version: older images do not start on the upgraded database. Go back with the backup taken before the upgrade:

```bash
cd ~/mentis
git checkout v0.6.1
./restore.sh "$(ls -1dt backups/mentis-* | head -1)"
docker compose up -d --build --remove-orphans
```
